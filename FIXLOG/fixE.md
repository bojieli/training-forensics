# FIXLOG: Fix-E (reader v2: non-round recipes)

All numbers: `results/fixe/FIXE.md` (generated by `scripts/fixe/report.py` from `results/fixe/{dev,stacks,fresh,v21}/*.json`).
Code: `trainforensics/recipe_v2.py`, `scripts/controlled/score.py` (v2 path, default; `TF_READER=v1` restores v1),
`tests/test_recipe_v2.py` (4 tests), `scripts/fixe/` (runs_fixe.sh, rescore.sh, report.py, probe.py).
Tags: `reader-v2-frozen` (before the fresh runs f01-f04 were trained), `reader-v2.1` (fallback for unconfirmed cases).

## What changed
- Weight decay is fit continuously from the bit-exact replay of never-updated weights; a round value is reported only
  when it reproduces exactly the same fp32 decay factors (the plateau of equivalent values is reported as `wd_interval`).
- The schedule shape is chosen among the move fit's candidates by a pattern search on the fraction of sampled
  never-updated weights the replay reproduces; that fraction is reported as `replay_select.conf`. Below 0.95 the recipe
  is flagged `recipe_recovered: false` (correct recipes reproduce 0.98-1.0); v2.1 then keeps the move fit's (v1) reading.
- New score fields: `recipe_ok.shape_exact`, `recipe_ok.decay_factors_exact` (non-round recipes can be exact in shape and
  factors while the peak and decay separately are known only to the move fit's precision, ~1e-4: the weights fix only
  the product peak x decay).
- Runs without weight decay are read exactly as before (the replay carries no information there).

## Results
- Development runs (motivated the fix): n03 (linear, decay 0.013) v1 read warm-up 18 / decay 0.015, 10 documents placed;
  v2 recovers shape and decay factors exactly, the seed, tokens via replay with 0 false positives, 1,113 documents placed
  (3 wrong). n05 (cosine-to-floor) and n02 (inverse_sqrt) are not recovered and are now flagged (confidence 0.59, 0.02).
- Regression: every earlier run with weight decay (r07, r08, r09, r11, r12, g01, q7_wd) and every training-stack run
  (t01, t02, t04, t08, t13, t16) reads exactly as under v1, with identical placement, seed and replay counts
  (t08, DeepSpeed's own kernel, via the v2.1 fallback).
- Fresh runs trained after the freeze, scored blind: f01 (linear 439 steps, warm-up 13, peak 3.3e-5, decay 0.027) and
  f02 (cosine 643 / 29 / 4.7e-5 / 0.019) fully recovered: shape and decay factors exact, seed found, tokens via replay
  exact (0 false positives), 1,132 (1 wrong) and 1,413 (2 wrong) documents placed; shifting the claim by one step leaves
  28 and 470 of ~25M never-updated weights matching. f03 (cosine-to-floor 557 / 41 / 2.1e-5 / 0.057) not recovered,
  flagged (0.55); f04 (inverse_sqrt, outside the reader's families) not recovered, flagged (0.08). No run was reported
  recovered when it was not.

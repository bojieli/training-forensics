## B1. Bit-identical counts and lineage

- **New per-comparison recount** (`scripts/frontier/recount.py` -> `results/frontier/recount/*.json`, `recount.json`),
  run on all 355 untied comparisons (roster, frontier_x, 2026 labs, large, gated). Per comparison:
  - `strict`: vectors equal to round(P x parent) (the sweep's `unmoved`);
  - `band`: vectors consistent with "parent x shrink, nothing else" allowing fp32 rounding drift (see M6);
  - `left`: band vectors minus unreachable tokens, added/reserved tokens, ids with no token string, vectors still at
    the parent's random start, all-zero rows (either model) and bit-duplicate child rows (logic from
    `scripts/tokens/negative_control.py` / `mine.py`). All-zero child rows are counted as `zeroed_edits`, never as
    bit-identical.
- **Negative controls** (`scripts/frontier/extras.py`, `calibrate.py` -> `results/frontier/calibration.json`,
  `negative_control_expanded.json`): 25 separately trained same-tokenizer pairs (Pythia deduped and seed variants,
  Qwen2 vs Qwen2.5 at 0.5B/1.5B/7B/72B) and 40 sibling pairs (two children of one parent, neither parent of the other).
  - Null pairs: largest `left` = 0. Qwen2-7B vs Qwen2.5-7B shares 2,282 vectors, all untrainable -> class
    "untrainable only". Null pairs classed "token record": **1/25 before -> 0/25 after**.
  - Siblings classed "token record": **17/40 before -> 13/40 after**. Expected: siblings share the trainable vectors
    neither post-training touched. So **no class names a direct parent**; the docstring now says so and the old
    comparability.py claim ("bit-identical vectors ... only a continuation of that base produces") is deleted.
- **Classifier** (`scripts/frontier/comparability.py`): `token record` needs `left >= T_LEFT` (= 50; null maximum 0)
  plus fit >= 0.99 or no resolvable shrink; new class **`untrainable only`** (shared vectors are all untrainable:
  shared random start, no lineage or data evidence); P accepted only in (0.5, 1.0] (minor 5); a comparison whose
  changes are >= 99% a 16-bit format round trip is `unchanged` (minor 10; per-comparison `roundtrip_explained`,
  `scripts/frontier/roundtrip.py`, zeroed rows excluded; no comparison reaches 99%).

## M4. "Changed throughout" threshold

Calibrated on the null pairs with no shared vector: largest fit 0.471 (pythia-2.8b vs deduped) -> `T_FIT` = 0.521
(was a fixed 0.5). Class name kept; meaning documented as "fit above every separately trained null pair".

## M5. `fit_decay_16` zero rows (trainforensics/diff.py)

All-zero parent rows are excluded from the sample; both the P = 1 and the least-squares neighbourhoods are searched;
the search maximises the fraction of matching *numbers* (smooth) and reports the fraction of matching rows. The
review's case (5 zero rows) now recovers P. Test added.

## M6. 16-bit resolution and fp32 drift

- **Drift simulation** (`scripts/frontier/drift_sim.py` -> `results/frontier/drift_sim.json`): untouched vectors after
  N fp32 decay steps, released in bf16. Strict match fails badly in some settings (N = 2,000, 1% decay: 3 / 1,000
  untouched vectors strict; 5% decay over 20,000 steps: 0 / 1,000); the band test admits all 1,000 in every setting and
  admits no updated vector at D >= 3e-6 (9 / 200 at D = 1e-6, the detection floor at d = 1,024).
- **Roster effect**: band != strict in **76 of 355** comparisons (123 have a resolvable shrink in 16 bit).
- **Per comparison** (recount records, comparability.json): `no_shrink_resolvable_below_pct` for the 180 P = 1 16-bit
  comparisons (median 0.195%, range 0.024%+), `detection_floor_10` (smallest per-number update that changes >= 10 numbers
  of a typical bit-identical vector; median 1e-5 of the median |value|), and the full histogram of the fraction of
  numbers changed (`hist_band`, `hist_strict`) instead of a fixed 1% bin.
- `detection_floor.py`: exactly-zero numbers no longer give a 1e-41 "floor"; adds the 1e-7 count.

## M7. P intervals

`scripts/roster/p_interval.py`: renamed "range of P that reproduces the same vectors (conditional on the fitted P; one
multiplication)"; widened by the largest simulated fp32 drift (`P_lo_drift`, `P_hi_drift`: 5.8e-4 relative, the
largest per-number drift in drift_sim.json); "partial rows" cases flagged `weak` and excluded from `decay_ranges.json` (21 ranges, was 23).

## M12. Tests

`tests/test_readers.py` (16 tests; with test_physics.py 24 pass): fit_decay_16 (incl. zero rows), moved_rows_16, interval_move (incl. the power-of-two
asymmetry), row_diff (fp32 decay, no decay), sweep.fit_decay / analyse (incl. zero rows), p_interval.interval,
comparability.classify (negative-control regression: Qwen2 vs Qwen2.5 is not a token record; zeroed rows), cosine_min and

`adam.schedule("wsd")` now matches transformers (no controlled run uses wsd with min_ratio > 0, so no result changes).

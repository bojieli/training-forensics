# DeepSeek special tokens and reserved placeholder slots

Generated by `scripts/frontier_ds/ds_report.py` from `deepseek.json` (made by `ds_tokens.py`) and `v4_change_shape.json` (made by `ds_shape.py`). Figure: `fig_b_deepseek_special_tokens.png` (`ds_fig.py`).

Every token in the vocabulary has its own vector of numbers. For each DeepSeek release we compare every special-token
vector with the same vector in the released base model the release was trained from:

- **bit-identical**: every number is the same. All DeepSeek comparisons show no weight decay on the token vectors
  (the sweep's fitted shrink is exactly 1), so an unchanged vector received no update large enough to flip a
  single 16-bit number. For a vector at its random starting size (about 0.51), one optimizer step at a typical
  post-training learning rate already flips a few percent of its 7,168 numbers, so bit-identical is strong evidence
  that the token was not in the post-training input.
- **barely changed**: under 1% of the vector's numbers differ (the STYLE.md threshold, the sweep's "near").
- **updated**: more numbers differ. The share of numbers changed is given wherever it matters: a vector with only
  a few percent of its numbers changed received one or a few tiny updates (a rarely seen token), while trained
  tokens typically show 50–100%.

We say what changed, never why. Nothing here is a claim about any lab's intent.

Named special tokens still exactly at their start in V3-Base: `<｜User｜>`, `<｜Assistant｜>`, `<｜tool▁calls▁begin｜>`, `<｜tool▁calls▁end｜>`, `<｜tool▁call▁begin｜>`, `<｜tool▁call▁end｜>`, `<｜tool▁outputs▁begin｜>`, `<｜tool▁outputs▁end｜>`, `<｜tool▁output▁begin｜>`, `<｜tool▁output▁end｜>`, `<｜tool▁sep｜>`.

**Why are the 800 placeholder vectors about 5x their starting size?** Three explanations, tested:

- *Rescaled start* would keep the start's direction (similarity to start = 1). Measured: 0.168. Ruled out.
- *Replaced by fresh random values* would leave no trace of the start (similarity about 0, within ±0.03). Measured: 0.148–0.189 (5th–95th pct), which is what a start of size 0.51 plus an independent change of size about 2.5 gives (0.51 / 2.54 ≈ 0.20). Ruled out.
- *Start plus a large change*, like ordinary trained tokens (similarity 0.081). Consistent. Since nothing shrinks or rescales vectors without a gradient here (no weight decay), the change came from the optimizer, i.e. the placeholders were in the pretraining input.
- The 800 changes point in a shared direction (pairwise similarity median 0.16, 5th–95th pct 0.07–0.25) while changes of random ordinary tokens do not (0.004; -0.03–0.05): the placeholders were updated together, as tokens that appear in the same kind of context would be.

**Verdict: holds-with-wording.** *Article sentence:* "DeepSeek-V3-Base's 800 reserved placeholder tokens are not empty: their vectors are about five times their random starting size, the starting values are still inside them, and the 800 changes share one direction, the signature of tokens that were in the pretraining input. The 465 unused slots beyond the tokenizer are still exactly at their random start."

- **V3**: 97 placeholder vectors differ from the base, all by tiny amounts (at most 7.9% of numbers; 87 of them above 1%), 76 of them in the contiguous block 128374–128449; their change size is about 1/25,000 of the vector. That is the pattern of a token touched in a handful of steps. V3-0324 has 96 of these 97 vectors exactly at the base values (it changed the 97th, 128421, itself), so the V3 vs V3-0324 comparison shows the same 97 vectors (87 above 1%, 10 below).
- **V4**: in the V4 bases the 800 original placeholder vectors are larger still (median size 8.2 in V4-Pro-Base). Both DeepSeek V4 releases (Flash and Pro) updated all 800; the 417 newer placeholder slots (ids from 128847 up) stayed bit-identical, so this is not a blanket operation on every vector. The third-party Nex-N2.5-Max, trained from the same V4-Pro-Base, left all 1,217 placeholders bit-identical.
- **R1-Zero** changed 10 vectors in slots the V3 tokenizer never produces (ids 128849, 128854, 128884, 128960, 129004, 129066, 129131, 129217, 129236, 129258; 8 updated, 2 barely). **Verdict: holds-with-wording** (V3: tiny changes, always state the share of numbers changed). *Article sentence:* "Post-training touches the placeholders too: DeepSeek's V4 releases updated all 800 original placeholder vectors while a third-party fine-tune of the same base left every one bit-identical; V3 changed 97 of them by tiny amounts (1–8% of each vector's numbers), 76 in one contiguous block."

Tests on `<｜political｜>`, `<｜safety｜>`, `<｜authority｜>` and their neighbours in DeepSeek's releases:

- **Starting point.** In both V4 bases these vectors are at the random starting size (0.50–0.51 in V4-Pro-Base, 0.38–0.39 in V4-Flash-Base, whose vectors have 4,096 numbers): pretraining did not use them. Any change is post-training.
- **Zeroed, copied, rescaled?** No release vector is zero, none is an exact copy of another token's vector (base or release), and none is a rescaled copy of its base vector.
- **Start still inside?** Yes: similarity to the base vector 0.994–1.000 in V4-Pro (change size 0.01–0.05) and 0.983–0.999 in V4-Flash (0.02–0.07); ordinary vocabulary tokens changed by a median 0.058 (V4-Pro) and 0.092 (V4-Flash). An overwrite with fresh values would remove the start.
- **Structured like training?** Across the ten tokens query/authority/domain/task/political/entity/title/safety/answer/search, the changes point in shared directions: 38 of 45 pairs (V4-Pro, median similarity 0.11) and 38 of 45 pairs (V4-Flash, median 0.13) exceed the 95th percentile (0.03) of random pairs of ordinary tokens. Independent noise or a per-token overwrite would not correlate; tokens that appear in the same kinds of sequences do.
- **Shape of the change.** The spread of change sizes across a vector's numbers matches both a trained token and Gaussian noise (median/mean about 0.84 for all), so this test cannot separate the two at these sizes; it is reported in `v4_change_shape.json` but not used as evidence.
- **Two model sizes.** The same pattern holds independently in V4-Flash (4,096 numbers per vector) and V4-Pro (7,168), and the tokens changed again in the 0731/0813 updates.
- **Is V4-Pro-Base / V4-Flash-Base the right reference?** Yes. 446 (Pro) and 447 (Flash) token vectors are bit-identical between base and release in every one of their numbers, including 14–15 named tokens and the 417 newer placeholder slots; that cannot happen by chance, so each release continues its base. No weight decay applies (fitted shrink exactly 1), so a changed vector was changed by the optimizer. The sweep's decay-fit score (91–92%, `RECONCILE.md`) is below 99% only because fewer than 512 vectors are untouched, so its 512-vector sample must include trained vectors; it is not evidence against descent.
- **Third party on the same base.** Nex-N2.5-Max left every one of these tokens bit-identical while updating the chat and tool tokens.

`｜DSML｜` and `<｜action｜>` are different: their release vectors are 9–24 times their starting size and show no trace of the start (similarity to the base vector between -0.02 and 0.02, where a start plus an independent change would give about 0.04–0.11). They were either re-initialised before training or trained so heavily that the start was erased; the weights cannot tell which.

**Verdict: holds-with-wording.** *Article sentence:* "DeepSeek V4's tokenizer defines tokens such as `<｜political｜>`, `<｜safety｜>` and `<｜authority｜>`. Pretraining never used them: in both V4 base models they are still at their random starting size. DeepSeek's own V4-Flash and V4-Pro releases changed them, by amounts of the same order as ordinary words and in directions shared across the group, which is what training on them looks like rather than an overwrite. A third-party fine-tune of the same base left them bit-identical. The weights say these tokens were trained; they say nothing about what for."

## Other observations (not article claims)

- Nex-N2.5-Max's chat and tool vectors (`<｜User｜>`, `<｜Assistant｜>`, the tool tokens) shrank uniformly by 0.11–0.14% with only a small further change, while 1,543 other vectors stayed bit-identical: consistent with weight decay applied only to vectors that received a gradient. V4.1-Flash-1017 shows the same on a few heavily used vectors (shrink 0.15–0.36%).
- The earlier editorial note that V4 releases are "not comparable to their base" does not hold for this test: ordinary token vectors keep similarity ≥0.999 to the base (5th percentile), and 4–15 named tokens per V4 comparison are bit-identical, so the release is a continuation of that base.

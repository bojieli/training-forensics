# Fix-E: reader v2 (recipe by bit-exact replay)

Generated by `scripts/fixe/report.py`. Reader v1 = before Fix-E (tag `fixc-frozen`); reader v2 = tag `reader-v2-frozen` (`trainforensics/recipe_v2.py`, `scripts/controlled/score.py`); v2.1 = tag `reader-v2.1`, which changes only runs the replay does not confirm (it then reports the move fit's reading, flagged).

**What changed.** Under decoupled weight decay every never-updated weight goes through fl32(x * fl32(1 - lr_t wd)) once per step, so a candidate recipe either reproduces those weights bit for bit or it does not. v1 searched the decay over round values only (1, 1.5, 2, 2.5, 3 ... x 10^k) and the step count over +-3 of the move fit. v2 fits the decay continuously (a round value is reported only when it reproduces exactly the same factors), chooses the schedule shape among the move fit's candidates by a pattern search on the fraction of sampled never-updated weights reproduced, and reports that fraction as a confidence; below 0.95 the recipe is flagged as not recovered (correct recipes reproduce 0.98-1.0). Runs without weight decay are read exactly as before: the replay carries no information there.

Columns: *shape exact* = schedule kind, step count and warm-up equal the trainer's; *decay factors exact* = the read learning rate x weight decay gives the trainer's fp32 decay factor at every step (the weights fix only the product peak x decay, so a non-round peak or decay is read to the precision of the move fit, ~1e-4, while the factors are exact); *tokens via replay* = updated tokens found by the bit-exact replay (needs the recipe), false positives in brackets.

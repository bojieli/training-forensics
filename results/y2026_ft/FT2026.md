# 2026 fine-tunes on 2026 bases: what their token vectors show

Generated by `scripts/y2026_ft/report.py` (Fork N2). Each fine-tune is compared with the base its model card
names (and, where that fails, with the likelier parent). Wording follows `STYLE.md`: a vocabulary token is
*updated* when more than 1% of the numbers in its vector differ from round(P x base), *barely changed* when 1 number
to 1% of them differ, *bit-identical* when none do. P is the uniform shrink from weight decay (P = 1: none).
Comparability classes as in `scripts/frontier/comparability.py`. Only the input embedding is compared.

ranked by downloads, likes and trending; quantized / GGUF / MLX / speculative-decoding drafts dropped), favouring

## Findings

### 1. NousResearch/Arete-27B against its published SFT set (`NousResearch/arete-data-pairs`)

Arete-27B's token vectors match its published SFT answers: 99.2% of the vocabulary in the training text was updated (63,392 of 63,900) and nothing outside it. The published reasoning traces were not trained on, as the dataset card states (0 of the 9,412 tokens that occur only in the traces were updated). The training text matches a plain concatenation of system prompt, question and answer without Qwen's chat markers, consistent with the per-example token counts Nous published (28,886 rows, 26,398,693 tokens); the marker vectors are therefore unchanged. Nous reports 28,886 training examples, 350 fewer than the published rows; the weights are consistent with a held-out set of that size.

Source of the corrected numbers: the independent check in `results/arete_check/` (logs `e_concat.log`, `f_final.log`). Our first pass (`audit_arete27b*.json`) tokenized with the Qwen chat template; it left 247 updated tokens apparently absent from the data. These are tokens such as `.Does` and `.What`, formed where the system prompt joins the question in the bare concatenation, so none remains unexplained.

**Pipeline lesson.** Always include the bare-concatenation format (system + prompt + answer + end token, no template) among the tokenization variants, and use the boundary tokens it creates (e.g. `.Does`, `.What` after `assistant.`) as a fingerprint of the format the trainer actually used. Chat markers left bit-identical are explained by this format before anything else.

### 2. Many popular 2026 fine-tunes leave no token record

- 13 of the 29 distinct fine-tunes (32 comparisons) have an input embedding bit-identical to the base: AEON-7/Qwen3.8-27B-AEON-ULTIMATE-UNCENSORED-BF16, ArliAI/Qwen3.5-27B-Derestricted, DavidAU/Llama3.3-8B-Instruct-Thinking-Claude-4.5-Opus-High-Reasoning, HemmingwayAI/Hemmingway-1, Jackrong/DeepSeek-V4-Pro-Qwen3.5-9B, OBLITERATUS/DeepSeek-V4.1-Flash-1017-obliterated, ProCreations/grug-27b, TeichAI/GLM-4.7-Flash-Claude-Opus-4.5-High-Reasoning-Distill, Tesslate/OmniCoder-9B, chromadb/context-1, jialinyyzz/humanizer, lordx64/Qwable-v1, xtools-at/DeepSeek-V4-Pro-Qwen3.5-9B-UNCENSORED-heretic.
- This matches the cards where they say it: LoRA on attention or linear layers (Qwable-v1, grug-27b), and refusal-direction edits ('abliterated', 'heretic', 'derestricted', 'uncensored') that leave the token embedding untouched.
- Shared input/output matrices erase the record: GLB-3D-Coder, NeoHorse-1-4B, VibeThinker-3B and AgentCPM-Explore changed every vector.

### 3. Lineage

- MemTensor/MemT-1.0-Flash names DeepSeek-V4-Flash as its base: 1,261 of its token vectors are bit-identical to V4-Flash, but 18,093 (plus 8,484 barely changed) to DeepSeek-V4-Flash-0731. Consistent with V4-Flash-0731 as the starting point. After removing untrainable rows: 16,806 vs 82 (V4-Flash) and 2 (V4-Flash-Base), which passes the margin rule (results/frontier/lineage.md). The 82 cleaned vectors MemT shares with V4-Flash are exactly the 82 that V4-Flash-0731 shares with V4-Flash: the same set, not just a similar count (results/frontier/sets.json).
- PrimeIntellect/INTELLECT-3.1 (card base GLM-4.5-Air-Base): not a decayed copy of that base (fit 0.017); against INTELLECT-3 every vector changed but a pure-shrink fit reproduces 0.969 of the closest vectors: but no cleaned vector (unreachable, reserved, at-init rows removed) is bit-identical to INTELLECT-3 (results/frontier/lineage.md), so the weights do not show which published model it started from.
- miromind-ai/MiroThinker-v1.5-30B: 1,924 vectors bit-identical and 4,413 barely changed against Qwen3-30B-A3B-Thinking-2507 (its card base); against Qwen3-30B-A3B-Base none (fit 0.022).
- IFM/K2-Think-V2 (fp32) is not a decayed copy of IFM/K2-V2-Instruct, the base its card names (every vector changed, fit 0.000).

### 4. fp32 releases: the recipe check

- HuggingFaceTB/nanowhale-100m (fp32, SFT on smol-smoltalk; card: 3,000 steps, cosine, peak 2e-5, 5% warm-up): 55,005 of 129,280 token vectors are near-pure shrinks of the base, by 0.0296% (weight decay about 0.01 under the card's schedule).
- Replaying that decay step by step does not reproduce them bit for bit: median error 147 fp32 steps under the card's cosine schedule, 202 under linear, 2196 under constant. The per-vector shrink also varies (0.9997024 to 0.9997059), which pure decoupled decay cannot do: these vectors received small updates besides the decay, so no exact replay or timing reading is possible. The shrink size is consistent with the card's schedule.
- microsoft/MagenticBrain (fp32 release of a Qwen3-14B fine-tune): 82,156 vectors bit-identical, 69,780 updated, only 302 seen in a single optimizer step. The schedule fit is weak (best wsd, 383 steps, coverage 0.38); no schedule is claimed.

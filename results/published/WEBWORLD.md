# WebWorld (8B, 14B, 32B) vs its published training set

Generated by `scripts/published/ww_report.py` from `results/published/webworld/` (`ww_tokens.py`, `ww_lengths.py`, `ww_compare.py`, `ww_finescan.py`). Method as in [PUBLISHED.md](PUBLISHED.md): every token in a model's vocabulary has its own vector of numbers; a token that occurs in the training text gets a gradient and its vector changes, a token that does not stays bit-identical to the base (here no uniform shrink: weight decay, if any, left no trace), and the final token of a sequence gets no gradient.

## Models, bases and data

- Models: Qwen/WebWorld-8B, -14B and -32B. Their Hugging Face card metadata names Qwen/Qwen3-8B as the base of all three; the WebWorld GitHub README names Qwen3-8B, Qwen3-14B and Qwen3-32B. The token vectors agree with the README: each model is compared with the Qwen3 model of its own size (the 14B and 32B vectors have 5,120 numbers, Qwen3-8B's 4,096).
- Data: `Qwen/WebWorldData`, `WebWorld_Training.jsonl` (52.2 GB), 1,107,028 conversations (the dataset card says 1,059,348), rendered with the Qwen3 chat template the models ship with and tokenized whole: 15,661,497,326 tokens, 142,952 distinct regular vocabulary tokens. Conversations are long: median 4,631 tokens, 130,387 longer than 32,768, the longest 6,080,005.

|---|---|---|---|---|---|
| Qwen/WebWorld-8B | whole conversations | 142,952 | 141,536 | 1,416 | 0 |

| Qwen/WebWorld-32B | first 20,000 tokens of each | 141,743 | 141,477 | 266 | 64 |

1. **Nothing outside the published set was updated.** Counting whole conversations, every one of the 141,536 changed regular tokens of WebWorld-8B occurs in the published data (14B: 0 changed tokens not in it; 32B: 2 changed tokens not in it).
2. **Almost everything in it was.** 141,536 of 142,952 regular tokens in the data changed (99.0%). The 1,416 that did not mostly occur only late in long conversations (median earliest position 31,299).
3. **The weights point to a training length limit near 20,000 tokens.** Counting only the first C tokens of each conversation, the number of changed tokens that are not in the counted text falls steeply up to C = 20,000 (145 at 19,000, 59 at 20,000) and barely moves after (55 at 21,000, 20 at 24,000), while the in-data tokens left bit-identical rise faster past it (266 at 20,000, 325 at 21,000). The best single limit in a 250-token scan is 20,000 at all three sizes. Leaving long conversations out entirely instead of truncating them fits worse (best: 349 mismatches against 325).
4. **The fit is not exact.** At a 20,000 limit, 266 tokens (0.19% of the data's vocabulary) occur within the first 20,000 tokens of some conversation but were never updated, and 59 changed tokens occur only later in their conversations. A different truncation rule, a different tokenization of some conversations, or published conversations that were not in the training run (the file holds 47,680 more conversations than the card's count) would each produce such a residual; the weights do not tell which. Unlike the s1.1 case there is no clean bracket.
5. **Same at three sizes.** 8B, 14B and 32B leave 10,122-10,127 vectors bit-identical with nearly the same mismatch counts: consistent with one training set for the series.
6. **Wrong-data control.** Scored against a set the models were not trained on (s1K-1.1), 114,364 changed tokens are 'not in the data' instead of 0.

## Special tokens

- Updated: `<|im_start|>`, `<|im_end|>`, `<tool_call>`, `</tool_call>`, `<think>`, `</think>` (the chat template inserts an empty `<think>` block in the final assistant turn).
- Bit-identical: `<|endoftext|>`, `<|object_ref_start|>`, `<|object_ref_end|>`, `<|box_start|>`, `<|box_end|>`, `<|quad_start|>`, `<|quad_end|>`, `<|vision_start|>`, `<|vision_end|>`, `<|vision_pad|>`, `<|image_pad|>`, `<|video_pad|>`, `<|fim_prefix|>`, `<|fim_middle|>`, `<|fim_suffix|>`, `<|fim_pad|>`, `<|repo_name|>`, `<|file_sep|>`, `<tool_response>`, `</tool_response>`. `<|endoftext|>` unchanged is consistent with one conversation per sequence (no packing).

## Verdict

Consistent with the published set: the token vectors of all three WebWorld models changed for the vocabulary of WebWorldData and for nothing outside it, with the pattern of a training length limit of about 20,000 tokens; a residual of about 325 tokens (0.2%) is not explained by a single length limit. The weights say nothing about why. The card metadata naming Qwen3-8B as the base of the 14B and 32B models reads as a metadata error; the README and the weights agree.

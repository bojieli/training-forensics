### Independent check: the optimizer state of the training run

Reproduce with `scripts/limo_check/run_all.sh` (inputs pinned in `scripts/limo_check/pins.py`; step logs and outputs in `results/limo_check/out/`). We do not redistribute GAIR's files; the run metadata below is read from them.

An earlier revision of the model repository (GAIR/LIMO@1833babb94e0b71051f8773911e2ece8ed6a0a51 (global_step234/bf16_zero_pp_rank_{rank}_mp_rank_00_optim_states.pt, deleted from main in 910230fdaaa8716a3fd8c521138cbe9e5019ddaf)) still holds the DeepSpeed ZeRO-3 optimizer state of the run; its 14 of 14 weight shards are byte-identical to the release. The fp32 master weights round to the released weights for 152,064 of 152,064 token vectors, and exactly 29,742 token vectors have a nonzero Adam second moment (equal to the changed set: True); every other row's master weight equals the base (largest difference 0.0). So every changed token received real gradients in this run, and every published token without a change received none.

**Token counts** (the published set rendered with the qwen chat template, first 16,384 tokens of each example): 13,386 distinct tokens, of which 13,183 changed and 203 did not; 16,559 changed tokens do not occur in the set (5,391 of them CJK; the published text has 46 CJK characters).

- **Run size.** Adam step 234 on every rank; 32 processes, per-device batch 1, gradient accumulation 1, 26 steps per epoch, so 801-832 examples per epoch (training_args.bin and trainer_state.json of the release; process count from the 32 optimizer partitions). The release is the epoch-9 checkpoint of a planned 15-epoch run (lr 5e-06, weight decay 0.0, resume_from_checkpoint None, output directory `aime817_deepseek-r1`). The run size excludes a larger corpus or extra datasets.
- **Questions.** All 3,440 question tokens received gradients, including 296 that occur in no solution (220 of them in a single question). Because 98.3% of all published tokens received gradients, this is consistent with the same questions rather than proof of them.
- **Solutions.** Published examples containing a token that never received a gradient, by assumed cutoff: 1,024: 19, 2,048: 33, 4,096: 46, 8,192: 57, 16,384: 61, 32,768: 76 (longest published example 35,341 tokens). The cutoff is not in the released files: GitHub `train_limo.yaml` said `cutoff_len: 32768` on the release day and `cutoff_len: 16384` from 2025-02-14 (04efb71); the paper says 16,384. The solution text used in training differs from the published one for at least 61 examples at 16,384 (76 at 32,768).
- **How many examples differ.** 654 of 817 published examples contain a token no other example has; in 596 of them every such token received a gradient. A published example contributes 7 such tokens on average (median 4, max 308). At that rate the 16,559 absent tokens would need about 2,336 differing examples (at least 54 even at the maximum rate), against the 61 we can flag and more than the 817 in the set. So the trained text of the differing examples must also be very unlike the published text (5,391 of the absent tokens are CJK). Detection is limited: 163 examples have no unique token, and an example whose unique tokens all reappear in its trained text cannot be flagged. The weights do not tell how many examples differ; "at least 61" is a floor, not an estimate.
- **CJK.** 5,402 of the 25,557 CJK vocabulary tokens received gradients.
- **total_flos** (3.69e+14) cannot be turned into a token count here: under ZeRO-3 the Trainer counts only the parameters that stay unpartitioned, and plausible choices give 14.9M, 6.1M, 6.1M, 10.3M tokens per epoch (published set: 5.67M at 16,384). We do not use it.

**Reading.** The released GAIR/LIMO checkpoint (epoch 9 of a 15-epoch run over 801-832 examples per epoch) received gradient updates on 16,559 distinct vocabulary tokens that do not occur in the published 817-example set, 5,391 of them CJK, while 203 distinct tokens of the published set never received one. The questions are consistent with the published ones; the solution texts used in training differ from the published ones for at least 61 examples, possibly far more. The run size excludes a larger corpus. The weights do not show what the other text was or why it differs.

**Evaluation sets: no implication of test-set training.** We do not report how many evaluation questions the changed tokens cover. Token coverage cannot show that a question was trained on, and it is dominated by language: LIMO's changed set contains 5,402 CJK tokens, so it covers many questions of the Chinese evaluation sets, which the control sets of known origin (LIMO-v2 and s1-32B, trained on other, English data) almost never cover. That restates that LIMO's trained text contained Chinese; it says nothing about which Chinese text. The counts are not published; `scripts/limo_check/deeper.py` writes them to a local file. We make no contamination claim.

# Pretraining weight decay, estimated from never-trained token vectors

Generated by `scripts/roster/pretrain_decay.py` from the checkpoint-forensics fingerprint cards.

Every token in a model's vocabulary has its own vector of numbers. Tokens that never occur in pretraining
(plus unused padding / reserved slots) keep their random starting values, except that decoupled weight decay
shrinks them by a factor (1 - lr x wd) at every step. checkpoint-forensics regenerates those starting values
exactly; the spread (std) that reproduces the published vectors bit for bit is init_std x P, where P is the
total shrinkage over pretraining. So the total weight decay applied is sum(lr x wd) = -ln P, and it needs no
checkpoints - but only if we know init_std, the spread the vectors started with.

How sure each row is:
- **validated** (8 Pythia models): init_std known, and the estimate agrees with an independent measurement from Pythia's public checkpoints to 1e-4 (table at the end);
- **exact, no decay** (5): the fitted spread equals a standard init value exactly, so no decoupled weight decay reached these vectors;
- **round number, likely no decay** (24): the fitted spread is a round number such as 0.006 (DeepSeek's paper init), which a decayed value almost never is; an inference, not a proof;
- **assumed init** (69): the estimate assumes the vectors started at the config's `initializer_range`; a different init convention moves P by ~2x, as Pythia shows;
- **implausible for decay alone** (20): under the assumed init, sum(lr x wd) > 15 (P < 3e-7); the vectors were rescaled or zeroed some other way, so no decay value is given;
- **init unknown** (12): no value.

which is why every non-Pythia row above that rests on `initializer_range` is marked as an assumption.

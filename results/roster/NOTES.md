# Roster sweep: interpretation notes (hand-written)

- Tied embeddings (32 pairs): the output softmax sends a gradient to every row each step, so the token record is gone (only 2 of 32 keep >=10 unmoved rows; 2 are unchanged). Same for untied output heads: 105 of 107 measured heads moved in >=99% of rows.
- "every row moved" (56 pairs) mixes: tied heads, re-initialised/rescaled embeddings, vocab-wide signals (e.g. merges, distillation with logit losses through tied weights), and a P that cannot be identified. P is only reported when >=10 rows are reproduced by round(P * parent).
- Kwaipilot/KAT-Dev-72B-Exp: fit returns P=0 on 2,171 rows => those rows are exactly zero in the child (zeroed, not trained). Its 22/22 "touched" control tokens are not a training signal.
- CORRECTED (exact intervals, `scripts/roster/p_interval.py` -> `p_intervals.json`): the "identical decay across families" (P = 0.994148 for Llama-3.1-8B/70B-Instruct, Llama-3.3-70B-Instruct, Nemotron-3-Ultra-550B, LLaDA-MoE-v2-30B) is a fitting artifact. In all five, every coordinate of the reproduced rows moved by exactly one bf16 step, which only confines P to [0.994141, 0.996124] (sum lr*wd in [0.0039, 0.0059]); 0.994148 is the lower edge of that interval, which any one-step shrink lands on. No shared recipe is implied.
- Qwen3-8B / 14B / 30B-A3B: exact interval P in [0.986911, 0.986979] for all three (sum lr*wd in [0.01311, 0.01318]; rows moved 2-3 bf16 steps) - consistent with one post-training schedule across sizes but not a proof, in the same way Qwen2.5 Instruct touches the same 4/22 control tokens at 7B/14B/32B/72B.
- Flat single-touch rows are rare in 16-bit releases (5 pairs with >=20). Lr values from them (~8e-7 for Llama-3-8B-Instruct and Mistral-Nemo-Instruct) rest on D only ~1-3 bf16 ulps and are weak; Hermes-4.3-36B D = 2^-7 exactly (lr 2.5e-4) looks like a rounding plateau, not a timestamp. Do not cite these as recovered learning rates without controlled-run validation.
- What is robust from public 16-bit releases: the exact set of rows that never moved (token never in a gradient), which control tokens a fine-tune used, and - when unmoved rows exist - the integrated lr*wd.

- Exact P intervals for every decay pair: `results/roster/p_intervals.json`. Report sum(lr*wd) as an interval; a point estimate is only as precise as that interval (0.002-0.01% wide for most pairs, 0.2% when every coordinate moved exactly one 16-bit step).
